## 3. The rule for an instance

In C2d an instance carries an arrow only if all of these hold, checked in this order:
1. **The room holds the order.** The first concept of FROM comes before the first concept of TO. DestinyTheGame failed this.
2. **Two turns, one reply.** The second line replies to the first in the same thread, at any depth, by another author, later in time. One turn holding both acts shows no order. It may illustrate a mechanism, but it never stands as the arrow's instance; that was ubc c0084.
3. **Both lines are cited.** Each concept sits under a third-order theme of its element.
4. **The first line's words do the FROM act**, read whole: a call calls, a start proposes or begins, upkeep defends or repairs. The coder's placement is necessary but not enough. "I'm in." under the call theme is a joining line, not a call.
5. **The second line's words do the TO act as a new act, answering the first.** Invoking an earlier treaty does not show upkeep bringing the room to talk. That was switzerland.
6. **The printed quote is the store's text,** with the hour and the interval, read through the verbs.

An instance that fails is reported as failing, not quietly swapped. Every arrow in the model text prints at least one instance that passes all six.
