## The method question, in one sentence

Can independently reconstructed case histories be composed into a shared dynamic account that supports explanations at successive levels of specificity, from population-wide patterns, through forms and subforms, to particular organizational histories, while keeping access to the evidence from which those explanations were developed?

The theory question is unchanged: when strangers organize on a clock they did not set, with no way to compel anyone and no goal given to them, what forms does organizing take, how do they differ in their functioning, and which of them keep the work alive?

## How the B1 walk goes (the stage file, kept here for after a compaction)

- **Legs.** One stretch of the order per leg, about 1 MB (`out/_analysis/b1_stretch_sizes.py <first> <last>`), declared in the diary when the leg opens. Then B1c (the saturation test), B1d (the second pass), B1e (the scheme standing, handback, interview cut).
- **The next room is always `mem.py next --stage B1`**, at every leg start and after every compaction. It follows the order and the stopping rule. Never a room from memory.
- **Startup packet each leg:** this head, the stage file, the last five diary entries, `mem.py scheme --brief` (paged at 80 lines: `--offset 80`, 160), `validate.py --open B1`.
- **Per room.** Read the A1 note (`mem.py note`) and every theme's note and concept labels; the room on its own first, then against read rooms tied to it. An episode needs both records to tell it, by one thread or one artwork in the same hours; a member writing in both rooms is strong evidence (`b1_shared_many.py` on dumps from `b1_dump_rooms.py $TMPDIR d_ <rooms>`, files `d_<room>.txt`; `b1_grep_rooms.py`; `b1_room_placements.py`). One member carrying the same call into several rooms counts (E249, E841, E846). Mark "same": "thread" only when both rooms' codes sit in that thread; otherwise "artwork". A member's name only from `cite.py` (one code per call). A room is done when every second-order theme is placed or listed in `unplaced-B1.jsonl` (Edit tool, `{"sub", "second_order", "theme_id", "label", "leg", "why"}`), only for a bare title or link. A theme that stands alone goes on the rare tier, not out.
- **The tie search.** `mem.py neighbours`, then `saturation.py order` for read status, then `b1_grep_rooms.py` on the read neighbours and on the rooms the codes name; read every match in full. Grep the episode file for the room's partners before writing a new line, and join an existing line where it tells the same event. An unread room's record is a lead, never an episode.
- **Episodes.** One line per event, listing every room that tells it; a joining room is added with "Added at B1b-NN" at the start of the evidence and the end of the why, through `b1_episode_join.py <spec.json> --leg <leg> [--write]` (Read the file's tail again before the next Edit). It applies only an episode's last entry per run; joins to different lines go in one spec, several joins to one line are split with `b1_split_spec.py <spec> <outdir>` and applied in turn. Describe members without naming them. List only kinds a listed room holds as placements; a kind held only in a bag does not count. Before closing, run `b1_episode_read_check.py <read_rooms_file>` and `b1_episode_theme_check.py <first> <last>` (numbers, not ids). Members take they and them.
- **Order of work in a room:** read every theme; log ideas and mint the room's new kinds first; then place the rest with `python3 out/_analysis/b1_place.py <sub> t01=T3-002 t02=T3-004,T3-103 ...` (timeout 600,000 ms; a comma places the theme in several kinds, the first the primary). Before choosing kinds for an unfamiliar theme, `b1_label_grep.py "<regex>"` and `b1_kind_labels.py <T3 id>` show how earlier themes were placed.
- **Rule 0, single placement.** One third-order theme per second-order theme, the one whose gate it meets best. A second or third only where a concept of its own supports it; a one-code theme takes one kind. Write the leg's table as a `.psv` with the Edit tool (header `sub|theme_id|primary|additional|codes|why_not_one`, one line per added kind, new lines before the `END|t00|` placeholder; cite only codes under that theme), place every kind with `b1_place.py` first, then convert the whole table with `grep -v "^END|" ... | tr '|' '\t'` and run `b1_multiplace_write3.py <tsv> --leg <leg> --write` (timeout 500,000 ms; it checks the scheme as written, so a kind not yet placed shows as a problem). Beyond three kinds: place once and record a bag through `b1_bags_from_file.py <tsv> <leg> <bagfile> [--write]` (bag lines `sub:tNN:T3-kept:T3-a,T3-b:why`, exactly four colons, no colon in the why), one bag file per room (`b1bNN_bags_<room>.txt`). Check with `b1_precheck_bagfile.py <bagfile>` after the placement, then `b1_check_bags.py <leg> <sub>`. Bag when the extra kinds have three or more concepts each and are named in the label or note; keep three when a fourth sits in one or two concepts, or is not named, and write the unnamed kind into the room note for B1d.

- **Verbs, never by hand.** `mem.py idea "<label>" --trigger <sub>:<tNN>`; `mem.py mint --label "..." --trigger <sub>:<tNN>`; `mem.py place <sub>:<tNN> --theme T3-NNN`; `mem.py unplace <sub>:<tNN> --theme T3-NNN`.
