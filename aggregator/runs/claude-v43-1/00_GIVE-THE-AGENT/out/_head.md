## The method question, in one sentence

Can independently reconstructed case histories be composed into a shared dynamic account that supports explanations at successive levels of specificity, from population-wide patterns, through forms and subforms, to particular organizational histories, while keeping access to the evidence from which those explanations were developed?

The theory question is unchanged: when strangers organize on a clock they did not set, with no way to compel anyone and no goal given to them, what forms does organizing take, how do they differ in their functioning, and which of them keep the work alive?

## How the B1 walk goes (the stage file, kept here for after a compaction)

- **Legs.** One stretch per leg, about 1 MB of codes and second-order themes (`mem.py room <sub> --size`; the forest is not counted), declared in the diary when the leg opens. Then B1c, B1d and B1e.
- **The next room is always `mem.py next --stage B1`**, at every leg start and after every compaction.
- **Startup packet each leg:** this head, the stage file, the last five diary entries, `mem.py scheme --brief` (paged at 80 lines: `--offset 80`, 160), `validate.py --open B1`.
- **Per room.** Read the A1 note (`mem.py note`) and every theme's note and concept labels; the room on its own first, then against read rooms tied to it. An episode needs both records to tell it, by one thread or one artwork in the same hours; a member writing in both rooms is strong evidence. One member carrying the same call into several rooms counts (E249). Mark "same": "thread" only when both rooms' codes sit in that thread. A member's name only from `cite.py`; quote a disputed or political code through `cite.py` before describing it. A member who only says they are from a room is not "a member who writes in" it; check the shared list, and count shared members without AutoModerator and [deleted] (`b1_shared_counts.py` includes them). A room is done when every second-order theme is placed or listed in `unplaced-B1.jsonl` (Edit tool, appended at the end), only for a bare title, link or reply.
- **The tie search.** `mem.py neighbours` (paged at 80 lines), `saturation.py order` for read status, partner dumps (`b1_dump_rooms.py $TMPDIR d_ <rooms>`, `b1_shared_counts.py`, `b1_shared_detail.py`) searched for the room's names and marks; read every match in full. Grep the episode file for the partners and the room's own name, and join an existing line where it tells the same event; a read room found telling it may join too. An unread room's record is a lead, never an episode. A room absent from `saturation.py order` is outside the census; check before writing either.
- **Episodes.** One line per event, listing every room that tells it; a joining room is added through `b1_episode_join.py <spec.json> --leg <leg> [--write]`, a dry run first. It applies one entry per episode per run; several joins to one line go in separate runs. Describe members without naming them; members take they/them. List only kinds a listed room holds as placements, not bags. Check the parse with `jq -c .episode out/episodes-B1.jsonl | wc -l` in a turn of its own after every write. Before closing, run `b1_episode_read_check.py <read_rooms_file>` and `b1_episode_theme_check.py <first> <last>`.
- **Order of work in a room:** read every theme; log ideas and mint the room's new kinds first; then place the rest with `python3 out/_analysis/b1_place.py <sub> t01=T3-002 t02=T3-004,T3-103 ...` (timeout 600,000 ms; a comma places the theme in several kinds, the first the primary). Before choosing kinds for an unfamiliar theme, `b1_label_grep.py "<regex>"` shows how earlier themes were placed.
- **Rule 0, single placement.** One third-order theme per second-order theme, the one whose gate it meets best. A second or third only where a concept of its own supports it. Write the leg's table as a `.psv` with the Edit tool (header `sub|theme_id|primary|additional|codes|why_not_one`, one line per added kind, new lines before the `END|t00|` placeholder; cite only codes under that theme), place every kind with `b1_place.py` first, then convert the whole table with `grep -v "^END|" ... | tr '|' '\t'` and run `b1_multiplace_write4.py <tsv> --leg <leg> --write`. Beyond three qualifying kinds: place once and record a bag through `b1_bags_from_file2.py <tsv> <leg> <bagfile> [--write]` after the rule 0 write (bag lines `sub:tNN:T3-kept:T3-a,T3-b:why`, exactly four colons, no colon in the why), one bag file per room. Check with `b1_precheck_bagfile.py <bagfile>` after the placement, then `b1_check_bags.py <leg> <sub>`. Bag when the extra kinds have three or more concepts each and are named in the label or note; keep three when a fourth sits in one or two concepts, or is not named, and write it into the room note for B1d. A room's placement count is its placed themes plus its rule 0 lines; check it before logging the note.
